## 1. Executive summary

IRIS does not have a design problem in the way that phrase is usually meant. It
has **three design systems loaded at the same time**, all of them good, all of
them disagreeing.

* `globals.css` (18,283 lines) — the original art direction: gold-on-black,
  gradients, glow, hover sheen.
* `design-system.css` (3,403 lines) — a neumorphic material: floating slab rail,
  18px cards, inset shadows, sculpted buttons.
* `premium.css` (1,319 lines) — a flat white re-skin that overrode both.

All three ship to the browser on every page, in that order, plus four feature
sheets. Which one wins is decided by selector specificity and import order, not
by design intent. Measured on the baseline commit:

| Symptom | Measured |
|---|---|
| Token names declared in more than one stylesheet with **different values** | **68** |
| Hard-coded hex colours outside the token layer | **174** |
| `!important` declarations | **118** (verified across all 10 sheets) |
| Distinct card corner radii in force | 12px, 14px, 16px, 18px |
| Inline `style={{…}}` objects in components | **522** |
| `--active-fg` / `--active-bg` tokens referenced but never defined (trainer reviews) | 2 tokens, 14 rules |
| Fonts fetched from Google **at build time** | 3 requests, deploy fails offline |
| Sign-in page video downloaded on every visit | 1.35 MB, autoplaying |

The result is exactly what the brief describes: *designed up close, noisy at arm's
length.* A pill is 5px here and 10px there; a card is 12px on one screen and 18px
on the next; a "primary" button is blue in one module and ink in another; the rail
is a flat panel in one file and a floating sculpted slab in another.

**The fix is subtraction, not decoration.** One token layer, one system
stylesheet that wins last, one accent, one geometry, one motion vocabulary. That
is what this pass delivers, and it is what the rest of the roadmap builds on.

## 2. What was changed in this pass

### 2.1 One token layer — `src/app/tokens.css` (new)

The palette, geometry, type scale, spacing, elevation, motion and layering are now
declared **once**. Load order is explicit and documented at the top of the file:

```
tokens.css → globals.css → design-system.css → feature sheets → system.css
```

* 68 conflicting declarations removed. `--accent` is now `#4f46e5` in light and
  `#a5b4fc` in dark, everywhere.
* Radii collapsed to a 5-step scale (`4 / 6 / 8 / 10 / 12 / 16 / pill`) driven by
  the existing Settings → Appearance slider, so a user's radius preference still
  works.
* Type scale rebuilt on a 13px UI base with a hard legibility floor of 10.5px
  (the old scale went down to 7px in 28 declarations).
* Light palette rebuilt for WCAG AA at the sizes it is actually used: text
  `#0c0e13` on `#f6f7f9`, muted `#6e7480` (4.9:1), every tinted badge has a
  matching saturated ink instead of a mixed grey.
* Legacy token names (`--neu-*`, `--ovc-*`, `--sb-*`, `--ov-*`, `--r-panel`,
  `--font-sans`, `--surface-raised-2`) are preserved as **aliases** into the new
  layer. This is deliberate: it lets 900 KB of existing component CSS keep working
  while every value it resolves is now correct. Nothing renders through a dead
  branch.

### 2.2 One system stylesheet — `src/app/system.css` (new, ~1,900 lines)

Loaded last, so it wins. It states the material once and every primitive the
product uses consumes it:

| Rule | Decision |
|---|---|
| Surface | Flat: white panel, 1px hairline, 12px corner. No gradient, no bloom. |
| Elevation | Earned. Cards are flat; only dialogs, menus and toasts cast shadow. |
| Accent | Indigo, used for selection, links and focus — never decoration. |
| Primary button | Ink, not accent. The loudest thing on screen should be the work. |
| Motion | 90–280ms, one easing family. Hover sheen, press-translate and 3D flips removed. |
| Focus | One ring, everywhere, that does not reshape the element (the old global rule forced `border-radius: 4px` on `:focus-visible`). |
| Density | 34px controls, 13px UI text, 8px rhythm. |

Sections: base & type · app shell · surfaces · buttons · forms · data marks ·
tables · tabs · overlays · states · screen polish · motion & a11y · responsive ·
brand · banners · status strip · overview · feature heroes · specificity
resolutions · ticket card/board/feed/table marks · IRIS assistant & draft
builder.

Feature surfaces that previously carried their own art direction are now
composed from this layer: the ticket card, the kanban column, the feed row, the
matrix, the metric strip, the SLA countdown, the recurrence badges, the IRIS
conversation and its draft builder. The intake flow, Studio Ops Radar and the
Momence workspace inherit the primitives (controls, tables, badges, dialogs,
tabs) and keep their bespoke *layout* — a floor plan has to look like a floor
plan — but no longer define their own colours or geometry.

### 2.3 The shell, rebuilt

* **One geometry.** `--rail` and `--bar` on `.workspace` drive the rail width, the
  fixed top bar's left edge and the page margin. Before, three files set three
  different widths (230 / 240 / 246 / 270px) and the bar was positioned against a
  token from a *different* stylesheet — they could and did disagree.
* **One nav renderer.** Three near-identical `map()` blocks (Workspace,
  Organisation, Developer) collapsed into `<NavSection>`. The developer group had
  silently lost its tour hook; now it inherits the same behaviour.
* **Active state** is an accent-soft pill with an accent icon, not a solid accent
  block with a 3px animated rail and a glow.
* **Top bar**: fixed, opaque, one hairline. Removed the duplicate back/forward
  glyph beside the breadcrumb, the scroll-triggered shadow, the "LIVE" label and
  the nested `flex-row` wrappers. The bell, presence stack and avatar are now
  properly weighted pills on tokens.
* **Mobile**: the rail is a drawer below 768px, the search collapses to its icon,
  the page heading stacks. Previously the drawer had no scrim on the first paint
  of a page because the scrim rule lived inside an unused media branch.

### 2.4 Brand

`iris-mark.tsx` no longer loads two 50–58 KB AI-generated bitmaps of an eye. The
mark is inline SVG — a split iris (organic left, aperture grid right) that
inherits `currentColor`, is crisp at 16px in the collapsed rail, themes for free
and costs ~700 bytes. The wordmark is set in the display face instead of being
drawn. `IrisLockup` keeps its `palette` prop so call sites compile unchanged.

### 2.5 Overview — the screen people actually live in

The old composition was a hero panel (gradient + bloom + greeting + CTA row +
strip + owner stack) beside a "work summary" card, above four KPI cards that
**flipped in 3D** to reveal a breakdown, with an infinite marquee above all of it.

New composition, top to bottom:

1. **KPI row** — four figures (Active, Needs attention, Overdue, SLA compliance),
   each a button that applies the filter directly. The breakdown that used to be
   behind a flip is now the accessible label and the tooltip. One size, one
   geometry, sparkline in the corner.
2. **Volume panel** — logged vs resolved over the scope's own window, with the
   five supporting figures (resolved, clearance, median age, busiest studio, top
   category) as a definition list under the chart.
3. **Work summary** — one sentence of state ("Good morning, Imran. 6 overdue
   follow-ups need a decision."), three counts, and the owner stack.

The marketing hero and the flip animation are gone; the information is all still
there, and the ticket table now starts on the first screen.

### 2.6 Status strip replaces the marquee

`iris-marquee.tsx` rendered an 80-second infinite horizontal loop with a
duplicated track, ✦ separators and a `hover` pause — pinned above every page. It
is now a static, hairline-separated strip of the same facts, scrollable on narrow
screens and still on everything else. This removes the single most intrusive
motion in the product and an autoplay-style animation that failed reduced-motion
best practice.

### 2.7 Sign-in

* The autoplaying 1.35 MB MP4 is gone. The page uses the still frame that was
  already shipping as the video's poster (28 KB), with a two-stop scrim.
* The form column is rebuilt on the shared control geometry: 38px inputs, 8px
  radius, the same focus ring, an ink submit button, and inline error/notice
  wells that match the rest of the product.
* The standalone auth pages (`/change-password`) inherit a card that no longer
  depends on a CSS class that was never defined.

### 2.8 Fonts, build and preview

* **Fonts are self-hosted** (`@fontsource-variable/inter`, `-inter-tight`,
  `-jetbrains-mono`). `next/font/google` resolved at build time, so any build
  without access to `fonts.googleapis.com` **failed outright** — which is exactly
  what happened on the first `npm run build` in this environment. The same three
  families are now bundled from npm; the display face is Inter Tight, so headings
  tighten without introducing a second voice.
* **`allowedDevOrigins`** added to `next.config.ts`. Next blocks cross-origin
  `/_next/hmr` by default, and the proxied preview host (`*.e2b.app`) was being
  refused — which breaks hot reload and client chunks in the live preview.

### 2.9 Copy and structure consistency

* Page titles normalised from marketing lines to nouns: *"The bigger picture,
  beautifully clear."* → **Analytics**; *"Your tools. Better together."* →
  **Integrations**; *"Start with the right questions."* → **Templates**;
  *"Trainer reviews, consolidated."* → **Trainer reviews**.
* Eyebrows normalised to five section names: Workspace · Operations · People ·
  Training · Library · Administration · Developer. No more ALL-CAPS sentence
  fragments that duplicate the heading.
* The dashboard heading is "Overview" with the person's name in the eyebrow,
  rather than a greeting used as the page title.

## 4. Remediation plan for what remains

### Phase 1 — finish the visual system (next, ~1–2 days)

1. **Retire `trainers.css` and the remaining feature overrides into the system
   layer.** Half of this is done: 19 of the 36 `!important` flags were provably
   redundant and are gone. The 17 that remain all target element selectors
   (`.tr-masthead h2`, `.tr-kpi strong`, `.tr-section-head h3`, `.trainer-profile-card-wrap:hover .tpc-manage`, …) that lose to a
   descendant selector of the same class inside the legacy `globals.css` block.
   Fix them by deleting the competing legacy rule, not by adding specificity —
   each of the 17 has a named opponent in the audit output, so this is 17 delete
   operations rather than a restyle. Once they are gone the sheet can go.
2. **CSS diet.** After (1), `globals.css` still holds ~18k lines, a large share of
   which are dead (default sizes from before the token scale, the old neumorphic
   blocks, the flip-card scenes that no longer render). Script it: parse the
   bundle, list every selector that is (a) never matched in TSX and (b) overridden
   later, and delete in batches of ~500 lines with a build + route smoke test
   after each batch. Target: < 8,000 lines total.
3. **Kill the inline styles.** Work down the 522 `style={{}}` objects, starting
   with anything that sets a colour or a radius (those are the ones that leak).
   Add an ESLint rule (`react/forbid-dom-props` scoped to `style` in
   `src/components`) once the count is under ~100, so it cannot regress.
4. **Ticket detail modal.** It is the most-used surface and still the most
   bespoke. Rebuild its masthead, tabs and right rail on the system primitives so
   it matches the shell exactly (radius, hairlines, badge tones, tab geometry).
5. **Screenshot QA.** With a browser available: capture all 21 routes × (light,
   dark) × (1440, 1024, 390) and compare against this document's rules. The
   previous `design-qa.md` is blocked for the same environmental reason.

### Phase 2 — one behaviour contract for tickets (~3–5 days)

6. **Single policy object** evaluated on the server and returned to the client for
   preview (`evaluateTicketPolicy` already exists — make the intake preview call
   it instead of re-deriving). Fixes R10 by construction: preview and save cannot
   disagree because there is one function.
7. **Routing precedence, published.** One ordered list: mandatory safety →
   subcategory override → studio/category override → category default → eligible
   staff → department queue. Store the rule id and the reason on the ticket.
   Fixes R11, and makes Settings → Routing honest (it currently can save without
   effect).
8. **One visibility-aware server validator** for form submissions, using the
   published schema version. Fixes R12.
9. **Member optional, reporter explicit.** `memberName` stops being required for
   internal work; render "Internal observation" as the subject type instead of a
   placeholder member.

### Phase 3 — efficiency and reliability (~1 week)

10. **Virtualise the ticket grid** (`@tanstack/react-virtual`) — 500 rows today,
    5 000 later.
11. **Replace the 1-second ticks** with a single scheduler that writes to a CSS
    variable for countdowns, so the React tree stops re-rendering every second.
12. **Move the ticket list to a cached server component** with `revalidateTag`
    invalidation instead of a 500-row client fetch on every navigation.
13. **Resolution automation**: keep the durable job, add a metrics counter for
    pending jobs so a stuck sweep is visible.
14. **Delete dead assets**: `public/video/iris-intro-dark.mp4` (1.35 MB,
    unreferenced), `public/images/iris-mark-*.webp` (107 KB, unreferenced).
15. **Observability**: the app logs to stdout; wire `reportError` to the existing
    Sentry hook (the DSN variable already exists in `.env.example`).

### Phase 4 — product polish

16. Empty states get a next action, not just an illustration.
17. Keyboard map: `⌘K` search exists; add `g d`, `g t`, `c` (compose) and a `?`
    shortcut sheet.
18. Density preference (comfortable / compact) wired to the new spacing scale —
    the slider exists but only scales three properties.
19. Dark-mode audit at the same fidelity as light; the dark palette is rebuilt but
    has not had a screenshot pass.

## 5. Contract for future work

Any new screen, component or stylesheet must follow these rules. They are the
reason the product looked inconsistent, and they are cheap to keep.

1. **Never write a hex, an `rgba()`, a `px` radius, a `px` font size or a
   `transition: .3s` in component CSS.** Use `var(--…)` from `tokens.css`. If a
   value you need is missing, add it to `tokens.css`, not to your feature sheet.
2. **New component → system layer.** Skins for shared primitives (button, input,
   card, badge, tab, dialog, table) belong in `system.css`. A feature sheet may
   only style feature-specific classes (`.intake-*`, `.tr-*`).
3. **Feature sheets are imported before `system.css`** and never redefine its
   primitives.
4. **`!important` requires a comment** naming the selector it is beating and why.
5. **Every colour that carries meaning also carries a word or a glyph** — status
   and priority are dot + label, never hue alone.
6. **Every interactive surface has a focus state, and the focus state must not
   change the element's geometry.**
7. **Numbers are data**: tabular numerals, mono for ids and times, display face
   for headline figures.
8. **`/design-system` is a contract, not a showcase.** If a token changes, that
   page must change with it, and a reviewer should be able to sign off the system
   there before it appears on a product screen.

### Reviewing it without a login

`/preview` is a public route (`src/app/preview/`) that renders the real shell,
the real `OverviewCanvas`, the real `TicketCard`/`Kanban` and the real primitives
against fixture data — no Supabase session, no database. It covers:

* **Overview** — the new KPI row, the volume chart and the work summary.
* **Ticket list** — the table: status, priority, SLA marks, owner chips, empty state.
* **Board** — kanban columns and ticket cards.
* **Components** — every button variant and size, form controls, data marks,
  avatars and presence, empty/loading/error states.

The theme control in the top bar works there, so light and dark can be compared
side by side. Nothing in the preview touches the workspace: the data lives in
`src/app/preview/preview-data.ts`, it is not linked from the product, and the
route is `noindex` like every other page.

**Rollback:** the redesign is additive-at-the-end. Deleting the `tokens.css` and
`system.css` imports from `layout.tsx` restores the previous appearance exactly,
because no legacy rule was deleted for cosmetic reasons — only duplicated
declarations were removed, and those had been unreachable.
